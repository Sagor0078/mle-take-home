# ML Rigour Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the proxy-based model evaluation with graded relevance labels, clustered-bootstrap statistics, a four-model sweep and cross-fitted ranking variants, and ship to the API only what the evidence supports.

**Architecture:** Labels and vocabulary live in `eval/labels/`; pure functions in `eval/labels.py`, `eval/metrics.py`, `eval/ranking.py`, `eval/stats.py`; embeddings for the sweep come from a subprocess worker (`eval/embed_worker.py`) so each model's time and peak memory are measured in isolation and cached; `eval/evaluate.py` orchestrates and writes `eval/results/<date>.md`. Product changes (Tasks 8–9) are conditional on the decisions the evaluation prints.

**Tech Stack:** numpy, fastembed 0.9.x, psycopg, pytest; existing app (FastAPI, Alembic).

**Spec:** `docs/superpowers/specs/2026-11-20-ml-rigour-design.md` (main system spec: `docs/superpowers/specs/2026-11-20-company-recommendations-design.md`).

## Global Constraints

- **Human gate:** after Task 1's commit, no metric, sweep or tuning runs against the real labels until the candidate has reviewed `eval/labels/activities.csv` and their version is committed (Task 5 starts with that check). Tasks 2–4 write code and unit tests on hand-built data only.
- Labels are drafted from the texts alone; no model output is consulted while drafting. `annotator` = `claude-draft` for every drafted row.
- Relevance: 2 = same activity (never for `industry_only`), 1 = same industry (from the companies table, both non-null), 0 otherwise.
- k = 4. Bootstrap: 2,000 resamples, percentile 95% CI, seed 0, resampling **activity clusters** (`industry_only` texts form one cluster per industry: `industry_only:<industry>`).
- Folds: 5, greedy balance by query count — clusters sorted by (−size, name), each into the fold with the smallest current total (lowest fold index on ties). Deterministic, no seed.
- Model adoption: nDCG@4 gain vs current with CI excluding 0 **and** mean gain ≥ 0.02 **and** embedding the corpus (≈180 texts) < 60 s.
- Variant ship rule: out-of-fold nDCG@4 difference CI lower bound ≥ −0.01 **and** target metric improves with CI excluding 0 (cap: redundancy@4 down; τ: pooled precision (grade ≥ 1) up).
- τ grid: 0.30 … 0.95 step 0.01; on training folds choose the smallest τ with pooled precision ≥ 0.90; none → no threshold for that fold.
- Ranking order everywhere = the API's: score desc, then same industry first, same state first, reg_no asc.
- Only API contract change allowed: `reason` may also be `"no_close_matches"`.
- Tests never download a model (`fake-hashed-bow` only). Env: `set -a; . ./.env; set +a; uv run ...`; never `just down`.
- Commit trailer: `Co-Authored-By: <your model> <noreply@anthropic.com>`.

## Review Focus

1. **A model that needs a prefix is embedded without it** (e5, embeddinggemma) → unfairly loses. Test in Task 4 (`test_worker_applies_spec_prefix`).
2. **Labels changed after results were seen** → every results file records the labels' sha256 and annotator counts. Test in Task 6 (`test_report_header_has_labels_hash`).
3. **Query or neighbour without an industry, or a fallback text** → grade is 0/1/2 by the rules, never an exception. Test in Task 2 (`test_grade_edge_cases`).
4. **Threshold leaves zero neighbours** → API says `no_close_matches`, not `no_description`. Test in Task 9 (`test_threshold_empty_reason`).
5. **A cluster with a single query, or all-equal values** → bootstrap returns a finite (possibly zero-width) CI, deterministically. Test in Task 3 (`test_bootstrap_degenerate_cases`).
